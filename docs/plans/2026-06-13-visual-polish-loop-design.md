# Frontis 官网视觉打磨循环（Visual Polish Loop）设计文档

日期：2026-06-13
状态：已确认

## 背景与目标

frontis.cn（衔远科技官网）为 Vite 构建的多页静态站，已有成熟设计语言
（量子黑 #000000 / 阈值青 #00C1D4 / 能量橙 #FA5F26，Space Grotesk + JetBrains Mono + 中文黑体）。
本次目标：**保留现有设计语言，对视觉细节全面打磨提质**，采用自动化
"截图 → AI 评审 → 修改 → 再截图" 的评分驱动循环，无需中途人工确认。

## 范围

- 页面（按执行顺序）：`index.html` → `horizon.html` → `leadeep.html` → `scene.html` → `about.html`
- 视口：桌面 1440×900、移动 390×844，均截全页
- 约束：无内容硬约束，视觉效果优先，文案结构可重组；但不得偏离黑/青/橙设计语言

## 方案选择

已对比三种方案，选定 **方案 A：全串行 + 独立评审子代理**：

- 评审者与修改者分离（每轮派发全新评审子代理，只看截图与评分标准），避免自评膨胀
- 页面串行执行，先完成的页面沉淀"风格基线清单"，保证跨页一致性
- 放弃并行方案的速度优势，换取质量与一致性

## 循环流水线

```
启动 vite dev（后台常驻，一次性）
对每页（按顺序）:
  轮次 n（硬上限 6 轮）:
    1. 截图：Playwright，1440px + 390px 全页 → outputs/loop/{page}/round-{n}/
    2. 评审：全新子代理，输入 = 截图 + 评分标准 + 设计语言说明 + 风格基线清单
       输出 JSON: { 总分, 各维度分, 问题清单[{位置, 严重度, 建议}] }
    3. 判停：总分 ≥ 9.0，或连续两轮提升 < 0.3 → 该页完成
    4. 修改：主会话按问题清单修改该页 HTML/CSS/JS
    5. 校验：npm run check，失败则回滚本轮修改
    6. 提交：每轮一个 git commit
  页面完成：取分数最高轮次为最终版；结论追加至风格基线清单
```

## 评审标准（10 分制）

| 维度 | 权重 | 关注点 |
|---|---|---|
| 排版与层级 | 25% | 字号节奏、行高、信息层级清晰度 |
| 间距与对齐 | 20% | 留白节奏、栅格对齐、模块呼吸感 |
| 色彩运用 | 15% | 黑/青/橙体系的克制与强调时机 |
| 细节质感 | 15% | 边框、阴影、圆角、图标精致度 |
| 移动端适配 | 15% | 390px 下布局、触控目标、字号 |
| 整体印象 | 10% | 高级感、与顶级 AI 官网的差距 |

偏离既有设计语言的改动计为扣分项。

## Git 工作流

- 工作分支：`visual-polish-loop`（自 main 切出）
- 提交粒度：每轮一个 commit，格式 `polish({page}): round {n} — {摘要}`
- 交付：推送分支至 GitHub，不动 main；附变更摘要供人工验收后合并部署

## 风险与兜底

| 风险 | 对策 |
|---|---|
| 静态截图看不到滚动动效 | 评审仅覆盖静态视觉；动效问题修改时人工把关 |
| 评分震荡不收敛 | 每页 6 轮硬上限；取最高分轮次为最终版 |
| 修改破坏功能 | 每轮跑 `npm run check`，失败即回滚该轮 |
| 共享组件改动影响已完成页面 | 改 components/* 后对已完成页面重新截图回归 |
